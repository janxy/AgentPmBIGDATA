# 海上全域感知大屏设计方案

## 一、项目概述

### 项目背景

原项目（`原项目/`）中已有一套海上监管大屏，功能覆盖目标融合、光电联动、轨迹分析、电子围栏等，能力完整但存在文件体量过大、信息架构复杂、视觉风格老旧、适配方式不统一等问题。本次在 `website1` 中独立重建新版海上监管大屏，原项目仅作为功能与业务参考，不修改原项目任何代码。

### 项目目标

1. **整体体验重塑**：保留核心业务能力，重构首页布局、目标面板、工具栏、告警弹窗的信息架构与交互路径。
2. **视觉风格升级**：不复制原版视觉，重新设计具有审美科技感的大屏视觉体系，观感显著优于原项目。
3. **值班监控优先**：面向日常盯屏与快速处置场景，提高信息密度与操作效率，同时保持演示级观感。
4. **Mock 数据驱动**：第一版使用内置 Mock 数据完整跑通核心链路，后续可平滑替换为真实接口。

### 核心价值

- 好看：建立统一、精致、有层次感的科技大屏视觉体系。
- 好用：目标监控、筛选、详情、告警联动链路短，值班人员能快速定位与处置。
- 可演进：地图内核组件化，数据层与 UI 层解耦，后续可接入真实海图与真实接口。

## 二、功能范围

第一版聚焦值班高频核心场景，整体按“核心场景优先”交付，以下功能全部纳入 v1.0：

### 1. 地图态势层

- 融合目标展示：AIS、雷达、北斗三源融合目标，区分目标类型（货船、渔船、客船、危险品船、其他）。
- 状态区分：在线、离线、异常目标使用不同颜色与标记样式。
- 缩放聚合：地图缩放时目标自动聚合/散开，聚合点展示数量。
- 悬浮提示：鼠标悬停显示目标名称、MMSI、航速、航向等关键信息。
- 点击定位：点击地图目标后联动打开右侧目标详情面板。

### 2. 目标监控

- 左侧目标列表：展示目标名称、MMSI、航速、航向、数据来源、状态。
- 多维筛选：按数据来源（AIS/雷达/北斗）、目标状态、目标类型、关键词搜索。
- 数量统计：地图目标总数、各来源数量、告警数量实时统计。
- 列表联动：点击列表项在地图上定位目标并打开详情。

### 3. 目标详情

- 基本信息：船名、MMSI、呼号、类型、国籍、尺寸、吃水。
- 实时动态：经纬度、航速、航向、更新时间、来源状态。
- 来源融合：展示 AIS/雷达/北斗各来源的数据质量与最近上报时间。
- 轨迹概览：目标最近轨迹折线预览与关键航迹点。
- 快捷操作：定位、跟踪、查看轨迹、发起告警处置入口。

### 4. 告警事件

- 底部告警滚动条：等级、类型、目标、时间实时滚动展示。
- 告警列表与详情：按等级/时间排序，支持查看告警详情。
- 地图联动：点击告警在地图上定位关联目标并高亮。

### 5. 工具栏

- 图层切换：显示/隐藏目标、轨迹、行政区划、雷达覆盖等图层。
- 目标样式：调整目标标记大小与轨迹尾迹显示。
- 复位视角：一键回到默认海图视角。
- 坐标拾取：点击地图拾取经纬度。
- 测距：在地图上绘制折线计算距离。
- 全屏：大屏全屏/退出全屏切换。

## 三、核心模块设计

### 1. 页面布局

- 整体采用 1920×1080 设计稿等比缩放，新增独立路由 `/maritime`。
- 布局结构：
  - 顶部 Header：平台标题、场景标签、系统时间、状态摘要、全屏/刷新入口。
  - 中央地图：全屏 Canvas 科技海图，作为页面视觉主体。
  - 左侧栏：可折叠，目标列表 + 筛选 + 统计，默认展开。
  - 右侧面板：可折叠，目标详情，默认收起，选中目标后展开。
  - 底部条：告警滚动 + 快捷入口。
  - 右侧竖排工具栏：图层、样式、复位、坐标拾取、测距、全屏。

### 2. 地图内核

- 采用轻量 Canvas 自绘海图方案，组件化封装为 `MaritimeMap`。
- 图层体系：海洋底图、网格、行政区划、雷达覆盖、目标层、轨迹层、交互层。
- 目标渲染：Canvas 绘制矢量标记与聚合圆点，支持缩放、平移、hover、点击。
- 视图状态：默认视角、缩放级别、当前选中目标、绘制模式（测距/拾取）统一由 store 管理。

### 3. 目标列表与筛选

- 列表数据来自 Pinia store 派生，按当前筛选条件实时过滤。
- 筛选交互：数据来源、状态、类型使用多选标签，关键词使用输入框。
- 列表项结构：状态点、船名、MMSI、来源图标、航速/航向、更新时间。
- 点击行为：定位地图目标、打开详情面板、高亮列表项。

### 4. 目标详情面板

- 面板采用右侧滑出式，支持收起为窄条。
- 信息分区：目标概览、实时动态、来源融合、轨迹概览、快捷操作。
- 来源融合区展示三源最近上报时间与数据质量，缺失来源显示降级态。
- 轨迹概览使用 Canvas 小图绘制最近轨迹折线。

### 5. 告警模块

- 底部滚动条按时间流展示最新告警，等级用颜色区分。
- 告警详情弹窗：告警类型、等级、目标信息、发生时间、处置状态。
- 地图联动：点击告警后定位目标、播放高亮动效、打开目标详情。

### 6. 工具栏

- 图层管理浮层：开关目标、轨迹、行政区划、雷达覆盖。
- 目标样式浮层：标记大小、轨迹尾迹开关。
- 复位、全屏为即时操作；坐标拾取与测距为模式化操作，进入模式后地图光标与提示同步变化。

### 7. 视觉设计

- 主色调：深空蓝黑背景 + 青蓝主光效 + 琥珀告警色 + 绿色安全态。
- 质感元素：细发光边框、角标、网格纹理、扫描光带、数字滚动动效。
- 信息层级：地图为主体，面板半透明深色玻璃质感，文字以高对比白/青为主。
- 动效原则：克制动效，仅用于状态变化、定位聚焦、数据刷新提示。

## 四、数据结构与流向

### 1. 核心数据实体

- `FusionTarget`：融合目标，字段含目标 ID、船名、MMSI、呼号、类型、国籍、尺寸、吃水、经纬度、航速、航向、状态、来源集合、更新时间。
- `SourceReport`：单源上报，字段含来源类型（AIS/雷达/北斗）、上报时间、数据质量、经纬度、航速、航向。
- `TrackPoint`：轨迹点，字段含时间、经纬度、航速、航向。
- `AlarmEvent`：告警事件，字段含告警 ID、类型、等级、关联目标 ID、发生时间、处置状态、描述。
- `MapViewState`：地图视图状态，字段含中心点、缩放级别、默认视角、当前模式。

### 2. 状态管理

- 使用 Pinia 拆分为四个 store：
  - `maritimeTargets`：目标列表、来源数据、轨迹、筛选条件、选中目标。
  - `maritimeAlarms`：告警列表、当前告警、联动状态。
  - `maritimeMapView`：地图视图、图层开关、绘制模式、测距结果。
  - `maritimeUi`：面板展开状态、工具栏浮层状态、全屏状态。

### 3. Mock 数据层

- Mock 模块提供初始化数据与定时刷新器：目标按 5 秒周期移动，告警按时间流新增，来源上报时间滚动更新。
- Mock 数据生成器独立于 UI，模拟真实接口返回结构，后续替换为真实 API 时仅改数据层。

### 4. 数据流向

- Mock → store → 派生筛选结果 → 地图/列表/统计同步渲染。
- 地图点击/列表点击 → 更新选中目标 → 详情面板打开。
- 告警点击 → 定位关联目标 → 地图高亮 + 详情联动。
- 工具栏操作 → 更新地图视图状态 → 地图重绘，UI 浮层同步。

## 五、边界情况处理

### 1. 数据异常

- 目标离线或来源数据超时：目标标记降级为离线样式，详情面板来源区显示“数据过期”。
- 告警关联目标不存在：仅执行地图定位与高亮，不打开目标详情。
- Mock 数据刷新失败：保留最后一次有效数据，并给出刷新失败提示。

### 2. 交互冲突

- 用户操作与 Mock 自动刷新冲突时，以用户操作为准，自动刷新不打断选中与筛选。
- 坐标拾取/测距模式下禁止目标点击，退出模式后恢复。
- 列表与地图同时选中不同目标时，以最后一次操作为准，双向同步。

### 3. 空态与降级

- 筛选/搜索无结果时展示空态提示，地图保留全部目标但高亮无匹配。
- 三源数据均缺失时，目标保留基本占位信息并标记“无来源数据”。
- 轨迹点不足时，轨迹概览显示“轨迹数据不足”占位。

### 4. 显示适配

- 1920×1080 等比缩放，窗口比例不符时按双轴 scale 适配并居中。
- 全屏切换后重新计算缩放，不重置地图视角与选中状态。
- 浏览器最小尺寸下自动收起面板，保证地图主区域可见。
